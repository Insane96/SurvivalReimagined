# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

This is a **Minecraft 1.21.1 NeoForge modpack instance directory** — not a Java/source code project. The primary author (Insane96) is the developer of two mods used in this pack: **InsaneSurvivalOverhaul** (ISO) and **RuneEnchanting**. The modpack serves as a playtest environment for those mods alongside compatible community mods.

There is no build system. Changes are made by editing config files and datapacks directly. Minecraft must be launched via CurseForge to apply changes.

## Applying config changes

- **Most ISO features**: require a Minecraft restart to take effect. A few (noted in the config) support `/reload`.
- **Data pack changes** (files under `datapacks/`): take effect with `/reload` in-game.
- **Gamerules** (`config/WSCommands.toml`, mod WSCommands): `gamerule` commands run on world join (`Repeat = true`, so they're re-applied every join).
- **`.toml.bak` files** are auto-generated backups — do not edit them, they are gitignored via `*.toml.bak`.

## Repository structure

| Path | Purpose |
|------|---------|
| `mods/` | JAR files for all installed mods |
| `config/insanesurvivaloverhaul/` | InsaneSurvivalOverhaul configs, split by feature category |
| `config/runeenchanting/` | RuneEnchanting system (`main.toml`, `runes.toml`) |
| `config/WSCommands.toml` | Gamerules applied on world join |
| `datapacks/survivalreimagined/` | Custom datapack for this modpack (nether tweaks, etc.) |
| `defaultconfigs/` | Per-world default configs (e.g. biome settings via Biolith) |

## InsaneSurvivalOverhaul config architecture

ISO uses a two-level config system:

1. **`config/insanesurvivaloverhaul/common.toml`** — master enable/disable switches for each feature module (Combat, Death, Farming, Hunger & Health, Items, Mining, Misc, Mobs, Movement, Sleep, World).
2. **Feature-specific JSON files** in `config/insanesurvivaloverhaul/<Category>/` — fine-grained overrides (e.g. custom terrain slowdown, energy boost items, echo pillar effects, mob equipment drop chances).

Many ISO features have a `"Data pack" = true` option that toggles an integrated data pack bundled inside the mod JAR. These are separate from files in the `datapacks/` directory.

## RuneEnchanting system

Vanilla enchanting is completely replaced by runes. Key points:
- `config/runeenchanting/runes.toml` — enable/disable each rune and tune its numeric values.
- `config/runeenchanting/main.toml` — global settings (hide items from creative, integrated data pack that removes enchanting table recipe).
- Emeralds are no longer converted to runes: they are the villagers overhaul's currency (the old `no_emeralds_datapack` was deleted).

## Active gameplay design decisions

Key non-obvious settings currently configured:
- **Nether portal** requires Crying Obsidian in corners (`Portal requires crying obsidian = true`).
- **Experience** is disabled via gamerule (`experienceoverhaul:disable_experience = true`).
- **Stone tools** are removed; copper fills that tier (`"Enable Stone tools gone" = true`).
- **Vanilla enchanting table** recipe is removed; runes replace enchantments.
- **Villagers come only from ISO's villagers overhaul** (since ISO 5.16.0.0, `Villagers overhaul` in `common.toml`, `[Mobs.Villagers]` in `server.toml`): villages are abandoned zombie villages, villagers are obtained only by curing zombie villagers, they only sell and emeralds come from rare ore, pillagers, fishing and advancements. Patrols, raids and the Wandering Trader are on (explicitly set in `config/WSCommands.toml`, so existing worlds that had them off are switched back). Villagers placed by structures are fine as long as they are few (e.g. prisoners): the DnT stronghold jail cell (2 villagers in 1 of 8 cells) and the villagers of DnT's Woodland Mansion are kept. They are unemployed with no stored trades, so they get ISO's trades when they take a job; check this for any new structure with villagers. Other villager sources stay off: Enhanced AI's witch "Dark art" (summons villagers) and Quark's `More Villagers`. **Woodland Mansions are DnT Woodland Mansion Replacement's Illager Manor**: the jar turns `minecraft:mansion` into an empty structure placed at the same spots (same salt and spacing), so explorer maps lead to the manor. Three of its chests use loot tables from the full Dungeons and Taverns mod (not installed): `nova_structures:chests/dungeon_6`, `dungeon_7` and `undead_crypts_grave` are defined in the datapack as the manor's `generic` table. DnT Ancient City Overhaul also ships `chests/illager_mansion/map_chest`, `secret_room` and `library_chest`, with maps to structures of the full mod: the datapack has copies of Woodland Mansion Replacement's versions so they always win (details in `MODS_STRUTTURE.md`). Abridged's pillager-infested bridge is still removed (to check whether its pillagers respawn like an outpost's). Structures that mods inject in village pools are disabled, as ISO's villages have no animals or job sites: Sawmill's Carpenter house (`carpenter_house_spawn_rate = 0`) and Incubation's Chicken Coops (its Blueprint remolders overridden with `noop` in `datapacks/survivalreimagined/data/incubation/remolders/`).
- **Villager trades follow ISO's rules** (1 emerald, sell only): mod items are added as trade files in `datapacks/survivalreimagined/data/survivalreimagined/insanesurvivaloverhaul/villager_trade/` and listed in ISO's per-level tags (`#insanesurvivaloverhaul:<profession>/level_<n>`). The Librarian's three enchanted book trades are overridden to sell a random non-curse Rune (`runeenchanting:set_random_rune`) for 1 emerald, the Weaponsmith's Shield to sell Shields+'s Iron Shield, plus the Copper (level 1), Golden (3) and Diamond (5) Shields; their second cost is 75% of their recycling (27 nuggets, 3 diamonds). Mod professions keep their own trades unless they get a trade set: Sawmill's Carpenter has one (`data/sawmill/insanesurvivaloverhaul/trade_set/carpenter/level_<n>.json`, `remove: all`) because its trades bought items for emeralds. Supplementaries' Red Merchant (spawns with the Wandering Trader, not handled by ISO) has its Moonlight trade files overridden in `data/supplementaries/moonlight/villager_trade/red_merchant/` with the same rules (1 emerald, few uses, 75% of the iron as second cost); its two lantern trades only load with Supplementaries Squared, not installed. Quark's `Add New Stones To Mason Trades`, `Add Crab Leg To Fisherman Trades` and `Zombie Villagers On Normal` are off (redundant with ISO). Only Quark's `Villagers Follow Emeralds` is on, Bits and Balance's duplicate is off. ISO's `/insanesurvivaloverhaul villager_trades dump` lists every trade, useful to check that mods (Vanilla Backport, Supplementaries, Ecologics) didn't slip trades past ISO's `remove: all`.
- **Supplementaries' Blast Armor Trim is fished as treasure**: Galleons (its only source) are disabled (`galleon = false`, their crew respawns from the structure's Moonlight `spawn_boxes`), so `datapacks/survivalreimagined/data/minecraft/loot_table/gameplay/fishing/treasure.json` is a copy of the vanilla table with the trim as a seventh weight 1 entry. A global loot modifier wouldn't work: `gameplay/fishing` rolls `treasure` as a nested table (see Vault loot).
- **Spawners** start empowered (burst of 20 mobs, then disable permanently) — the Spawner Reactivator item exists in ISO but is **disabled** in this pack (`"Re-enable with Spawner Reactivator" = false`), so disabled spawners cannot be reactivated.
- **Sleeping** requires tiredness (gained through exhaustion); phantoms spawn from tiredness not insomnia.
- **Nether roof** and 8:1 ratio are kept (the data pack option to disable them is set to `false`).
- **Echo Pillar** (ISO respawn-anchor feature) is **disabled** (`"Enable Echo pillar" = false`).
- **Storage Drawers**: upgrades, keys and the other extras are removed via `insanelib:creative_removal` and `insanelib:recipe_removal` (not the config). Compacting Drawers (2 and 3 slots, Half, Framed) are enabled with their default recipes. The Controller and Controller IO (and their Framed versions, made in the Framing Table) are enabled, with their recipes overridden in `datapacks/survivalreimagined/data/storagedrawers/recipe/` to also need 2 Hoppers in the bottom corners.
- **Ecologics' Azalea wood is replaced by Quark's**: the `ecologics:azalea_tree` feature is overridden in `datapacks/survivalreimagined` to place `quark:azalea_log` (Ecologics replaces the vanilla tree, which would otherwise make Quark's wood unobtainable), and Ecologics' 31 Azalea wood items (including the Vanilla Backport shelf) are in `insanelib:creative_removal` and `insanelib:recipe_removal`. Quark's set is kept for existing worlds. Ecologics' worldgen isn't configurable in `config/ecologics-common.toml`: use biome modifier overrides (e.g. its Nether gold veins are `neoforge:none`). Its leaves don't drop saplings (crafted with shears) and its buttons and pressure plates need redstone, via overrides for each wood type: a new wood needs the same overrides (Vanilla Backport's Pale Oak and Poplar have them too).
- **Every Compat wood blacklist**: `config/everycomp-hazardous.toml` blacklists `ecologics:azalea`, `ecologics:flowering_azalea` and `bitsandbalance:azalea`, the Azalea sets not used in this pack. `config/everycomp-entries.toml` only hides recipes and creative tabs and still registers the blocks; the hazardous blacklist prevents registration, so changing it after release removes blocks from existing worlds. `resourcepacks/survivalreimagined_lang` overrides Bits and Balance's Pale Oak log models because their `#side` particle breaks Every Compat's model generation.
- **Quark's `[oddities]` category** (Totem of Holding, Pipes, Magnets, Crate, Backpack, Tiny Potato) only works with the separate "Quark Oddities" addon jar (`mods/QuarkOddities-*.jar`), now installed. The base `Quark-*.jar` contains the oddities classes, recipes and assets (`org/violetmoon/quark/addons/oddities/`) and generates their config sections, but confirmed in-game: the content does not appear without the addon. Enabled: Crate (`Max Items` 1280), Magnets, Pipes (`Pipe Speed` 10, slower than the default 5), Totem of Holding (`Dark Souls Mode` false). Disabled: Backpack, Tiny Potato. Pipes' default recipe: copper ingot / glass / copper ingot (vertical) → 6 pipes.
- **Totem of Holding replaces Gravestone**: on death the items go into Quark's Totem of Holding instead of a grave block. With `Dark Souls Mode` false the totem is not destroyed if the player dies again before recovering it.
- **ISO's Death inventory penalty is on** with `death_keep_equipment` (set in `config/WSCommands.toml` with `death_durability_penalty 15`): worn armor, the offhand and hotbar items with durability stay in the inventory losing 15% durability, the rest drops into the Totem of Holding. With `death_keep_equipment` on, the other item and experience game rules are ignored; `keepInventory` must stay false or the feature does nothing.
- **Matrix Enchanting** is explicitly set to `false` even though it's a `[tools]`-category (not oddities) Quark feature that *would* otherwise work — disabled on purpose since RuneEnchanting already removes the vanilla enchanting table.
- **Naturalist follows the pack's food rules**: furnace recipes for its food are disabled, raw items are in `insanesurvivaloverhaul:raw_foods` and meat drops are reduced via loot table overrides in `datapacks/survivalreimagined` mirroring ISO's Livestock pack (since 5.15.1.0): 40% chance, +20% per Looting level (`random_chance_with_enchanted_bonus`), 1 meat, or 1-3 for big animals like ISO's Pigs (Boar, Elephant, Rhino, Mammoth); adults in a lifespan tag still drop double. If ISO changes its livestock loot again, these should follow. Ostrich's drumstick and feathers were in the same pool (one or the other), so the feathers got their own pool with a 50% chance. `naturalist:cooked_egg` is removed in favor of `incubation:fried_egg`, and `ecologics:crab_meat` (which is already cooked) in favor of `naturalist:cooked_crab_meat`; Ecologics' Crab Claw recipes and Tropical Stew use the latter. Quark's Crabs are disabled.
- **Parrot Eggs come only from Vibrant Parrots**: Quark's `"Parrot Eggs"` is off, as it needs Beetroot Seeds (hard to find). Vibrant Parrots makes Parrots breedable with `#minecraft:parrot_food` (also vanilla's taming food), which ISO's Livestock pack replaces with Melon and Pumpkin Seeds only (renewable, crafted from the fruit with ISO's Crops pack). ISO also puts Parrots in `prevent_breeding`, `breedable_animals` and `really_high_lifespan`, so they fall in love on their own and die of old age. The egg comes from Vibrant Parrots' `vibrantparrots:gameplay/parrot_lay` gift table.
- **Incubation's Nests are removed** (Hay and Twig Nest in `insanelib:creative_removal` and `insanelib:recipe_removal`, its three `add_feature` biome modifiers overridden with `neoforge:none`): nest-laying is hardcoded to Blueprint's `EggLayer` mobs and to Environmental/Autumnity eggs, so only Chickens used them, not Naturalist's Ducks. The mod is kept for its egg foods (Fried Egg, Scrambled Eggs) and Egg Crates.
- **Naturalist mobs are excluded from `enhancedai:speed_bonus`** (`remove` list in `datapacks/survivalreimagined`), like Endermen and Witches in Enhanced AI's own tag: they were too fast with its movement and swim speed bonus. Horses, Donkeys, Mules and Skeleton Horses are removed too, as their speed comes from ISO's Equine attributes. Enhanced AI's `outside_nerf` targets the same tag, so they also skip its -25% outdoor follow range.
- **Modded arrows are crafted in the Fletching Table** (ISO's `insanesurvivaloverhaul:fletching` recipes): crafting grid recipes for Spectral Arrows and new Rope Arrows are disabled in `datapacks/survivalreimagined`. The Rope Arrow recipe hardcodes `minecraft:damage` 24 (8 ropes out of the default `capacity = 32` in `config/supplementaries-common.toml`), so it must change with that value. Refilling stays in the crafting grid because Fletching results are fixed.
- **Strongholds use `random_spread`** (80/40) instead of DnT Stronghold Overhaul's rings, via `structure_set/strongholds.json` in `datapacks/survivalreimagined`. `#minecraft:has_structure/stronghold` is replaced with `#minecraft:stronghold_biased_to` minus `minecraft:mushroom_fields` (NeoForge `remove`: the islands are small, so strongholds ended up in the sea) to make those biomes required (checked at the start height, not the surface), and `structure/stronghold.json` is a copy of DnT's with `project_start_to_heightmap` `WORLD_SURFACE_WG` and `start_height` -64 (the portal room starts 64 blocks below the surface instead of at a fixed Y -15, which kept it underground under hills), `dimension_padding.top` 0 instead of 238 (capped pieces at Y ~81) and `terrain_adaptation` `none` instead of `encapsulate` (wrapped surface pieces in terrain), so its corridors, whose stairs always go up, sometimes reach the surface: recopy it if DnT updates that file. Eyes of Ender use the current placement, so in existing worlds old ring strongholds are no longer located.
- **Hellish Trials' `exclusion_zone`** is lowered from 10 to 5 chunks in `datapacks/survivalreimagined`: `minecraft:nether_complexes` is at spacing 16/8 here (DnT Fortress), not vanilla's 27/4, and with 10 chunks only about 0.4% of attempts survive, so the structure almost never generates. Worldgen overrides need a restart and only affect new chunks.
- **ISO's Reversible stonecutting** links every 1 to 1 stonecutting recipe between full blocks into families that can be cut into each other, so a downgrade recipe becomes a smelting skip. Tiny Takeover Backport's `minecraft:cobblestone_from_stone_stonecutting` and `cobbled_deepslate_from_deepslate_stonecutting` merged Stone with Cobblestone and Deepslate with Cobbled Deepslate, so they are disabled with `neoforge:false` in `datapacks/survivalreimagined/data/minecraft/recipe/`. After adding or updating mods with stonecutting recipes, check `/insanesurvivaloverhaul stonecutter_families dump` (`logs/insanesurvivaloverhaul/`) for families joining a raw block with its smelted version.
- **Rune loot for modded tables goes in `datapacks/survivalreimagined`** as `runeenchanting:rune_loot` modifiers, like the ominous vaults of Hellish Trials and Moog's Nether Structures (`survivalreimagined:loot/nether_vault` tag). Modifiers run in pack order and `runeenchanting:catch_all` would convert the loot first, so the datapack's `global_loot_modifiers.json` lists `catch_all` again after them, which moves it last.
- **Progressive Bosses replaces the Elder Guardian's loot table** (`progressivebosses:entities/elder_guardian_<level>`, set on the entity), so anything added to `minecraft:entities/elder_guardian` (Better Tridents' Trident Fragment, the Tide template) is lost unless nested. The pack's overrides of those tables nest the vanilla one plus 1/3/5 Wet Sponges. Its Elder Guardian Spike and Nether Star Shard are in `insanelib:creative_removal` and their recipes (`progressivebosses:trident`, `nether_star`) are disabled with `neoforge:false`.
- **Vault loot**: global loot modifiers only run on the table a vault rolls directly (`reward`, `reward_ominous`), not on nested ones like `reward_rare`, as `NestedLootTable` uses `getRandomItemsRaw`. To add loot on top, target the main tables (`survivalreimagined:add_vault_normal_loot`); to compete in a pool, override the table (Shortbows in vanilla, Hellish Trials and Moog's Nether Structures tables). Adventure Dungeons' vaults use the vanilla tables.

- **Crawling uses Bits and Balance's crawl** (`enableCrawlingMechanic = true`, key C in `config/defaultoptions/keybindings.txt`), not Personality's (unbound): Bits and Balance (seen in 2.5.9) clears any `SWIMMING` forced pose every tick on client and server when its own crawl is not active, even with the mechanic disabled, so Personality's crawl stood back up immediately.
- **Supplementaries' rope slide is off** (`slide_on_fall = false` in `config/supplementaries-common.toml`): it removes vanilla's -0.15 descent clamp on `#supplementaries:fast_fall_climbable` (Ropes and Ropes with Buntings), so players free fell down Ropes. Ropes now behave like Ladders, including ISO's Better Climbable (faster descent when looking down).
- **Supplementaries' Ash and ISO's Burnt Logs**: when fire consumes a log, ISO (InsaneLib's `BlockBurntEvent`, before vanilla re-reads the block) turns it into a falling Burnt Log with `"Burnt logs chance"` (0.8), leaving air, so Supplementaries' Ash (Moonlight's `IFireConsumeBlockEvent`, later in `checkBurnOut`) only forms from the other logs and from non-log solid blocks. To compensate, the Burnt Log's loot table is overridden in `datapacks/survivalreimagined` to also drop 1-4 Ash (not with Silk Touch): if ISO changes that table, follow it. `ash_from_fire_chance` is only checked against 0 in Supplementaries' code, not used as a chance.
- **Food overrides in `item_components` are base values**: since ISO 5.14.4.0 its food formulas (`server.toml` > `Foods & Drinks`) are applied on top of them, so the in-game values are `ROUND(nutrition * 1.2)` and `saturation * 1.4`, and eating time comes from the formula. To get a final value, write it divided by those factors (e.g. Tropical Stew 5 / 6 -> 6 / 8.4).
- **EMI info pages** (`emi:info`) go in `resourcepacks/survivalreimagined_lang/assets/emi/recipe/additions/` (the `emi` namespace is required: EMI ignores other namespaces), one file per page with `stacks` (`item:ns:id` or `#item:ns:tag`) and `text` as translation keys, whose text goes in `assets/survivalreimagined/lang/en_us.json`. Each file is prefixed with its mod ID (e.g. `supplementaries_rope.json`). Pages for behaviour that comes from Insane96's own mods (ISO, Enhanced AI, Progressive Bosses, RuneEnchanting, Stamina, No Hunger, ...) don't go in the pack: list them for the user, who adds them to the mod's EMI plugin. Only behaviour coming from the pack's combination of mods, configs and datapacks gets a page here.
- **Mob info pages are in Field Guide**, not EMI (an exception to the EMI rule above: they include behaviour from Insane96's mods). Mobs are unlocked by looking at them with a Spyglass (bosses by killing them), and the book opens with B or the inventory button. Each mob has one lang key, `fieldguide.<ns>.<mob>.description` in `resourcepacks/survivalreimagined_lang`, generated by `tools/emi_mobs/write_pages.py` from the `pages_*.py` batches (pass them all in one call). Foods are not listed in the texts: they say to search `#<mob>_food` in EMI, which matches the tag IDs. Mobs whose food is hard-coded or whose tag has another name get a reference tag `survivalreimagined:<mob>_food` in `datapacks/survivalreimagined/data/survivalreimagined/tags/item/` (named in `en_us.json` as `tag.item.survivalreimagined.<mob>_food`): it is only for EMI, editing it changes nothing in game. A new mob with food needs its query checked against the tag IDs (e.g. `#horse_food` also finds `#minecraft:zombie_horse_food`, so the Horse uses `#minecraft:horse_food` via `FOOD_QUERY`). ISO's breeding fail chance and twins hook `BabyEntitySpawnEvent`, so mobs whose babies come from eggs or pregnancy (Naturalist's `EggLayingBreedGoal`, Ecologics' Penguin) get the `breeds_alone.no_twins` shared text instead of `breeds_alone`. The texts say where the mob spawns, as the biome and drop grids are off in `config/fieldguide-server.json`: the drop grid ignores global loot modifiers, the biome grid needs Immersive Overlays (not installed). Spawn eggs are hidden in EMI (`assets/emi/index/stacks/survivalreimagined_spawn_eggs.json`). Until blocks and items are added, the Plants category is hidden and the `fieldguide:mushroom_collector` advancement is disabled (`datapacks/survivalreimagined/data/fieldguide/`). Animals and Monsters list every registered entity (by `MobCategory`, `MISC` only with a spawn egg), and the "complete the category" advancements need all of them: unreachable mobs go in `fieldguide:blacklisted`, like Quark's, which stay registered with its `mobs` category off. Check this for every new mod with mobs.
- **Hiding items in EMI**: `c:hidden_from_recipe_viewers` (which includes `#insanelib:creative_removal`) only removes them from EMI's item list, not from recipes. `resourcepacks/survivalreimagined_lang/assets/emi/index/stacks/survivalreimagined.json` removes `#item:insanelib:creative_removal` with `"disable": true`, which also hides every recipe that uses them.
- **Vanilla Backport's recipes are generated in code** (Platform's `DynamicRecipeManager`), not read from the `data/vanillabackport/recipes/` JSONs in its jar. A generated recipe is skipped when a non-vanilla pack has a file with its ID under `recipe/`, so disable one with a `neoforge:false` override in `datapacks/survivalreimagined/data/vanillabackport/recipe/` (like `cake.json`, whose `Blocks.CAKE` result resolved to Ecologics' Maple Cream Pie: without Farmer's Delight the pie's item uses the Cake block, so it takes over the Cake's block-to-item mapping and its name; the name is fixed with `minecraft:item_name` in `item_components/maple_pie.json`).

## When mods are updated

Updated jars show up in `git status` as a deleted old jar plus an untracked new one. For each updated mod:

1. **Read what changed.** For Insane96's own mods (ISO, Enhanced AI, InsaneLib, RuneEnchanting, ...) use the source repos in `C:\Users\delvi\source\repos\Insane96\<Mod>`: `changelog.md` plus `git log`/`git diff --stat` between the version commits (commit messages are the version numbers). For third-party mods, use their changelog (CurseForge/Modrinth/GitHub) or unzip the jar.
2. **Check the config.** After the game has run with the new jar, `git diff config/` shows new or changed options. A changed *default* is not applied to an existing value: the changelog says when an option must be updated manually. Don't edit the `.toml.bak` files.
3. **Look for conflicts with the pack's overrides.** Grep `datapacks/`, `defaultconfigs/` and `resourcepacks/` for the IDs, files and tags the update touches (loot tables, `item_components`, recipes, MPR presets, tags). An override may now be redundant (the mod does the same thing), overwrite an upstream fix, or rely on behaviour that changed. Overrides that mirror a mod's design (e.g. Naturalist loot mirroring ISO's Livestock pack) may need to follow the new values.
4. **Look for new integrations** the pack can use, or pack work that was waiting for this update (e.g. changelog entries already describing it).
5. **Update `changelog.md`** under `# Upcoming` > `Updated Mods`, alphabetically: `<Mod> <old> -> <new>`, where `<old>` is the version of the last release. If the mod is already listed there, only change the new version and merge the sub-bullets. Sub-bullets list only the changes players notice in this pack (skip disabled features, internal fixes, code/API changes), rewritten in the pack's style. A newly added mod only gets `Added <mod>`.

## Legacy content on the `v3` / `v2` branches

Before this pack was updated to 1.21.1, datapack/resourcepack content lived under
`global_packs/required_data/<pack>/data/...` and `global_packs/required_resources/...`
(the CurseForge "global packs" convention), instead of today's `datapacks/survivalreimagined/`.
That structure no longer exists on `1.21.1`, but it's still reachable on `origin/v3`
(and `origin/v2`) via `git show origin/v3:<path>` — it contains custom advancements,
recipes, and other content that was never ported to the current version. When adding
new datapack content (advancements especially), check whether v3 already solved the
same problem before designing from scratch — some of it references mods no longer in
this pack (e.g. `map_atlases`, `easel_does_it`, `heartstone`, `labels`, `betterdungeons`,
`nova_structures`) and should be skipped, but plenty is still directly portable.
